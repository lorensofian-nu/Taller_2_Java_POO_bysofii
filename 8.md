Impacto Práctico: Agregación vs. Composición en Entidades de Software


- Vinculación del Ciclo de Vida: En la Agregación, los objetos constituyentes tienen un ciclo de vida independiente de la clase contenedora. En la Composición, el objeto hijo existe únicamente en función del objeto padre; no puede sobrevivir de forma autónoma.

- Responsabilidad de Instanciación: En una Composición, el objeto contenedor es responsable directo de crear las instancias de sus componentes dentro de su propio constructor. En una Agregación, los objetos contenidos son creados externamente y pasados como parámetros (vía constructor o métodos setter).

- Control de Referencias y Encapsulamiento: La Composición protege de manera estricta la referencia interna contra manipulaciones o suplantaciones desde el exterior, impidiendo que terceros reemplacen el componente o accedan a él sin la mediación de la entidad principal.

## Requerimientos de Modelado de Entidades:

- 1. **Personaje** equipa **Arma** (Unidireccional **0..1**): La clase Personaje guarda un atributo de tipo Arma. Si el valor es null, el personaje combate desarmado.

- 2. **Personaje** <-> **Gremio** (Bidireccional **0..*** a **1**): Un personaje pertenece como máximo a un gremio, mientras que el gremio almacena múltiples referencias a sus personajes inscritos.

- 3. **Escuadron** agrupa **Personaje** (Agregación **0..***): El escuadrón mantiene una lista táctica de combatientes. La destrucción del escuadrón no altera el estado individual de sus integrantes.

- 4. **Personaje** contiene **CorazonRPG** (Composición **1..1**): Es el núcleo de atributos vitales del personaje. No existe personaje sin corazón, ni corazón sin personaje.

## 2. Implementación de Asociación Unidireccional y Bidireccional

## 2.1. Asociación Unidireccional: Equipamiento de Objetos ( Personaje -> Arma)

En la asociación unidireccional, la clase origen mantiene un atributo que referencia a la clase destino,

pero la clase destino desconoce la existencia del origen.

A continuación, complete la estructura básica de la clase Personaje para administrar el equipamiento

de un Arma:

```java
public class Personaje {
    private String nombre;
    private int nivel;
    private Arma armaEquipada;   // Asociación Unidireccional (0..1)
    private Gremio gremio;       // Asociación Bidireccional (0..* a 1)
    private CorazonRPG corazon;  // Composición Fuerte (1..1)

    public Personaje(String nombre, int nivel) {
        this.nombre = (nombre == null || nombre.trim().isEmpty()) ? "Héroe Sin Nombre" : nombre.trim();
        this.nivel = Math.max(1, nivel);
        this.armaEquipada = null; // Inicialmente desarmado
        this.gremio = null;       // Inicialmente sin gremio
        // Composición Fuerte: Se instancia internamente en el constructor
        this.corazon = new CorazonRPG(this.nivel * 100, this.nivel * 50);
    }

    public void equiparArma(Arma nuevaArma) {
        if (nuevaArma == null) {
            System.out.println("No se puede equipar un arma nula.");
            return;
        }
        // Asignar 'nuevaArma' al atributo 'armaEquipada'.
        this.armaEquipada = nuevaArma;
        // Imprimir un mensaje confirmando el equipamiento del arma.
        System.out.println("¡" + this.nombre + " ha equipado: " + nuevaArma.getNombre() + " (+" + nuevaArma.getDanioBase() + " daño)!");
    }

    public void desequiparArma() {
        // Validar si 'armaEquipada' no es null.
        if (this.armaEquipada != null) {
            String anterior = this.armaEquipada.getNombre();
            // Si tiene arma, reestablecer 'armaEquipada' a null e informar al usuario.
            this.armaEquipada = null;
            System.out.println(this.nombre + " ha desequipado: " + anterior + ". Ahora combate desarmado.");
        } else {
            // Si no tiene arma, emitir un mensaje indicando que no hay arma para retirar.
            System.out.println(this.nombre + " no tiene ningún arma equipada para retirar.");
        }
    }

    public int calcularAtaqueTotal() {
        int ataqueBase = this.nivel * 5;
        // Si 'armaEquipada' no es null, sumar su daño base al 'ataqueBase'.
        if (this.armaEquipada != null) {
            ataqueBase += this.armaEquipada.getDanioBase();
        }
        // Retornar el valor final calculado.
        return ataqueBase;
    }
}
```

¡ADVERTENCIA DE SEGURIDAD EN MEMORIA! Antes de invocar cualquier método o acceder a

atributos de un objeto referenciado (como armaEquipada.getDanioBase()), es una obligación estricta verificar que la referencia no sea null mediante un bloque condicional ( if (this.armaEquipada != null)). Omitir este control provocará de inmediato la excepción en tiempo de ejecución

NullPointerException.

## 2.2. Asociación Bidireccional y Sincronización Cruzada ( Personaje <-> Gremio)

Mantener la coherencia de las asociaciones bidireccionales en memoria requiere que ambos extremos

de la relación se mantengan sincronizados explícitamente. Si un Personaje se une a un Gremio, el Personaje debe actualizar su atributo gremio, y simultáneamente el Gremio debe incluir al Personaje dentro de su lista de miembros.

## Algoritmo de Sincronización en Doble Vía:

- 1. Invocación Inicial: El cliente llama a personaje.unirseAGremio(nuevoGremio).

- 2. Validación de Permanencia Previa: Personaje verifica si ya está inscrito en un gremio diferente. Si es así, debe desvincularse invocando previamente el retiro de dicho gremio.

- 3. Actualización de Referencia Propia: Personaje asigna nuevoGremio a su atributo local this.gremio.


- 4. Sincronización Cruzada Inversa: Personaje invoca a nuevoGremio.agregarMiembro(this),

evitando la recursión infinita validando si el personaje ya se encuentra en la lista interna del gremio.

Complete las definiciones de sincronización bidireccional en el código de las clases correspondientes:

```java
// Sincronización dentro de la clase Personaje
public void unirseAGremio(Gremio nuevoGremio) {
    // Validar si 'nuevoGremio' es idéntico al actual para evitar redundancias
    if (this.gremio == nuevoGremio) {
        return;
    }
    // Si ya pertenecía a un gremio diferente, desvincularse previamente
    if (this.gremio != null) {
        Gremio gremioAnterior = this.gremio;
        this.gremio = null; // Romper enlace local primero para evitar recursión infinita
        gremioAnterior.expulsarMiembro(this);
    }
    // Asignar el nuevo gremio al atributo local 'this.gremio'
    this.gremio = nuevoGremio;
    // Invocación cruzada: Asegurar que 'nuevoGremio' registre este personaje en su lista
    if (nuevoGremio != null && !nuevoGremio.getMiembros().contains(this)) {
        nuevoGremio.agregarMiembro(this);
    }
}

// Sincronización dentro de la clase Gremio
public void agregarMiembro(Personaje p) {
    // Validar que 'p' no sea null
    if (p == null) {
        return;
    }
    // Verificar si la lista de miembros no contiene ya a 'p' y añadirlo
    if (!this.miembros.contains(p)) {
        this.miembros.add(p);
    }
    // Sincronización cruzada: Si 'p.getGremio()' no es 'this', invocar p.unirseAGremio(this)
    if (p.getGremio() != this) {
        p.unirseAGremio(this);
    }
}
```

Reflexión sobre el Ciclo de Vida: Note cómo, a medida que avanzamos de referencias unidireccionales a

asociaciones bidireccionales cruzadas, la vida de las entidades se entrelaza fuertemente en la memoria Heap de Java, demandando metodologías estrictas para el alta, baja y modificación de enlaces.

## 3. Agregación vs Composición en Java

## 3.1. Agregación: Gestión del Escuadron (Relación Débil)

La Agregación modela una relación del tipo "tiene-un" de carácter débil. Los componentes existen de

forma ajena al contenedor. Si una instancia de Escuadron es eliminada o su referencia se reasigna a null, los objetos de la clase Personaje que la conformaban siguen plenamente activos e intactos en el sistema.

Desarrolle la clase Escuadron siguiendo los requisitos planteados:

```java
import java.util.ArrayList;
import java.util.List;

public class Escuadron {
    private String nombre;
    private List<Personaje> miembros; // Agregación (0..*)

    public Escuadron(String nombre) {
        this.nombre = (nombre == null || nombre.trim().isEmpty()) ? "Escuadrón Anónimo" : nombre.trim();
        this.miembros = new ArrayList<>(); // Inicialización de la colección
    }

    public void reclutarPersonaje(Personaje p) {
        // Validar que 'p' no sea null y que no esté ya dentro de 'miembros'
        if (p == null) {
            System.out.println("No se puede reclutar un personaje nulo.");
            return;
        }
        if (!this.miembros.contains(p)) {
            // Agregar 'p' a la lista 'miembros' sin alterar la instanciación original de 'p'
            this.miembros.add(p);
            System.out.println(p.getNombre() + " reclutado al escuadrón " + this.nombre);
        } else {
            System.out.println("El personaje " + p.getNombre() + " ya está en el escuadrón.");
        }
    }

    public void expulsarPersonaje(Personaje p) {
        // Remover 'p' de la lista 'miembros' si existe
        if (p != null && this.miembros.remove(p)) {
            System.out.println(p.getNombre() + " expulsado del escuadrón " + this.nombre);
            // Nota: 'p' mantiene su estado, vida y objetos intactos en memoria (Agregación Débil).
        }
    }

    public String getNombre() {
        return nombre;
    }

    public List<Personaje> getMiembros() {
        return new ArrayList<>(this.miembros); // Copia defensiva
    }
}
```

## 3.2. Composición: Encapsulamiento del CorazonRPG (Relación Fuerte)

La Composición representa una relación de pertenencia absoluta y excluyente. El CorazonRPG es una
parte constitutiva del Personaje. Debe ser instanciado dentro del constructor de Personaje y no debe existir ningún método público de tipo setter que permita reemplazar la instancia del corazón por una externa.

```java
public class CorazonRPG {
    private int saludBase;
    private int manaBase;

    public CorazonRPG(int saludBase, int manaBase) {
        this.saludBase = Math.max(1, saludBase);
        this.manaBase = Math.max(0, manaBase);
    }

    // Getters y métodos de manipulación interna de vida/maná (sin setters destructivos)
    public int getSaludBase() {
        return saludBase;
    }

    public void setSaludBase(int saludBase) {
        this.saludBase = Math.max(0, saludBase);
    }

    public int getManaBase() {
        return manaBase;
    }

    public void setManaBase(int manaBase) {
        this.manaBase = Math.max(0, manaBase);
    }

    public void curar(int cantidad) {
        if (cantidad > 0) this.saludBase += cantidad;
    }

    public void recibirDanio(int danio) {
        if (danio > 0) this.saludBase = Math.max(0, this.saludBase - danio);
    }

    @Override
    public String toString() {
        return "[Salud: " + saludBase + ", Maná: " + manaBase + "]";
    }
}
```

## 3.3. Multiplicidad y Colecciones en Java

Traducir la multiplicidad de un diagrama UML a código Java requiere seleccionar la estructura de

almacenamiento adecuada según las características de la relación:

```
Multiplicidad UML (0..1 o 1..1) ---> Atributo Directo (ej: private Arma arma;)
Multiplicidad UML (0..* o 1..*) ---> Estructura de Colección (ej: List<Personaje>
miembros;)
```

- Multiplicidad **0..1** o **1..1**: Se declara un atributo del tipo directo de la clase asociada. Si es 0..1, la referencia acepta valores null; si es 1..1, debe garantizarse la inicialización inmediata.

- Multiplicidad **0..*** o **1..***: Se utiliza una interfaz de colección ( List<T>) instanciada con una clase concreta como ArrayList<T>. Esta estructura habilita la expansión dinámica en memoria.

Transición a la Arquitectura Global: Con las piezas teóricas e implementaciones individuales de cada

tipo de relación listas, es el momento de unificar todas las clases dentro de un flujo ejecutable e interactivo de consola.

## 4.1. Integración en el Menú Interactivo en Consola

El reto integrador requiere construir una interfaz textual de consola que permita al usuario gestionar la

## Requerimientos del Sistema:

- 1. Control de Flujo: Implemente un ciclo do-while respaldado por una estructura switch para navegar las opciones del sistema.

- 2. Formateo de Salida: Utilice System.out.printf para generar tablas y reportes formateados de las estadísticas de los personajes y sus escuadrones.

## Plantilla del Menú Principal a Implementar:

```java
import java.util.ArrayList;
import java.util.List;
import java.util.Scanner;

public class AplicacionArenaRPG {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        int opcion = 0;

        // Colecciones globales para listar Gremios, Escuadrones y Personajes
        List<Personaje> personajes = new ArrayList<>();
        List<Gremio> gremios = new ArrayList<>();
        List<Escuadron> escuadrones = new ArrayList<>();

        do {
            System.out.println("\n=== MENÚ ARENA DE HÉROES RPG ===");
            System.out.println("1. Crear Personaje");
            System.out.println("2. Crear Gremio");
            System.out.println("3. Reclutar Personaje a Escuadrón");
            System.out.println("4. Equipar Arma a Personaje");
            System.out.println("5. Mostrar Estado Detallado (Personaje y Corazón RPG)");
            System.out.println("6. Salir");
            System.out.print("Seleccione una opción: ");
            opcion = Integer.parseInt(scanner.nextLine().trim());

            switch (opcion) {
                case 1:
                    // Solicitar nombre e instanciar un nuevo Personaje
                    System.out.print("Ingrese nombre del personaje: ");
                    String nombre = scanner.nextLine().trim();
                    System.out.print("Ingrese nivel del personaje: ");
                    int nivel = Integer.parseInt(scanner.nextLine().trim());
                    // Composición 1..1: CorazonRPG se instancia dentro del constructor de Personaje
                    Personaje p = new Personaje(nombre, nivel);
                    personajes.add(p);
                    System.out.printf("Personaje '%s' creado con éxito (Corazón: %s).%n", p.getNombre(), p.getCorazon());
                    break;

                case 2:
                    // Solicitar nombre e instanciar un nuevo Gremio
                    System.out.print("Ingrese nombre del Gremio: ");
                    String nombreGremio = scanner.nextLine().trim();
                    Gremio g = new Gremio(nombreGremio);
                    gremios.add(g);
                    System.out.printf("Gremio '%s' fundado con éxito.%n", g.getNombre());
                    break;

                case 3:
                    // Seleccionar un Personaje existente y agregarlo a un Escuadron (Agregación)
                    if (personajes.isEmpty()) {
                        System.out.println("No hay personajes registrados.");
                        break;
                    }
                    if (escuadrones.isEmpty()) {
                        System.out.print("No hay escuadrones. Ingrese nombre para crear uno: ");
                        escuadrones.add(new Escuadron(scanner.nextLine().trim()));
                    }
                    Escuadron esc = escuadrones.get(0);
                    Personaje pEsc = personajes.get(0);
                    esc.reclutarPersonaje(pEsc);
                    System.out.printf("'%s' reclutado al escuadrón '%s'.%n", pEsc.getNombre(), esc.getNombre());
                    break;

                case 4:
                    // Instanciar un Arma y asignarla a un Personaje (Asociación Unidireccional)
                    if (personajes.isEmpty()) {
                        System.out.println("No hay personajes registrados.");
                        break;
                    }
                    Personaje pArma = personajes.get(0);
                    System.out.print("Ingrese nombre del arma: ");
                    String nArma = scanner.nextLine().trim();
                    System.out.print("Ingrese daño base del arma: ");
                    int danio = Integer.parseInt(scanner.nextLine().trim());
                    Arma arma = new Arma(nArma, danio);
                    pArma.equiparArma(arma);
                    break;

                case 5:
                    // Construir reporte usando StringBuilder e imprimir estadísticas con System.out.printf
                    StringBuilder sb = new StringBuilder();
                    sb.append("\n================ ESTADO DETALLADO ARENA RPG ================\n");
                    System.out.print(sb.toString());

                    System.out.printf("| %-15s | %-5s | %-12s | %-20s | %-15s |%n",
                            "Nombre", "Nivel", "Ataque Total", "Arma Equipada", "Corazón RPG");
                    System.out.println("-----------------------------------------------------------------------------");
                    for (Personaje per : personajes) {
                        String armaDesc = (per.getArmaEquipada() != null)
                                ? per.getArmaEquipada().getNombre() + " (+" + per.getArmaEquipada().getDanioBase() + ")"
                                : "Desarmado";
                        String corazonDesc = "HP:" + per.getCorazon().getSaludBase() + " MP:" + per.getCorazon().getManaBase();
                        System.out.printf("| %-15s | %-5d | %-12d | %-20s | %-15s |%n",
                                per.getNombre(), per.getNivel(), per.calcularAtaqueTotal(), armaDesc, corazonDesc);
                    }
                    break;

                case 6:
                    System.out.println("Cerrando la Arena de Héroes...");
                    break;

                default:
                    System.out.println("Opción inválida.");
            }
        } while (opcion != 6);
    }
}
```

## 5. Puntos de Depuración y Diagnóstico en IntelliJ IDEA

## 5.1. Detección de Desbordamiento de Pila ( StackOverflowError)

Un error clásico al implementar relaciones bidireccionales en Java ocurre al invocar recursivamente el

método toString(). Si Personaje.toString() imprime los datos de su Gremio, y a su vez

Gremio.toString() itera e imprime el toString() de cada uno de sus miembros, el programa entra en un ciclo infinito de llamadas cruzadas hasta agotar la pila de llamadas del sistema, lanzando un

java.lang.StackOverflowError.

```
Personaje.toString() ---> Gremio.toString() ---> Personaje.toString() --->
StackOverflowError
```

## Pasos para Diagnosticar y Solucionar con el Depurador de IntelliJ IDEA:

- Fijar Breakpoints: Coloque un punto de interrupción (Breakpoint) dentro de la primera línea del método toString() de la clase Personaje.

- Ejecutar en Modo Debug: Inicie la aplicación presionando el ícono de insecto o mediante la combinación Shift + F9.

- Inspeccionar la Pila de Llamadas (Call Stack): Abra la ventana inferior Frames / Call Stack. Si observa que las llamadas a los métodos Personaje.toString() y Gremio.toString() se repiten alternadamente cientos de veces, ha confirmado la recursión circular.

- Solución de Código: Rompa la cadena de llamadas en uno de los dos lados de la relación. En Gremio.toString(), limite la impresión de los miembros a únicamente sus nombres o identificadores simples, evitando volver a llamar al toString() completo del objeto Personaje.

## 5.2. Diagnóstico de Referencias Nulas y Desincronización
